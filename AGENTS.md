# Repository Guidelines

## Project Structure & Module Organization
- `server.js`: Express server that serves the UI and handles `/api/links` and `/api/status`.
- `public/index.html`: Single-file frontend (HTML/CSS/JS) for the dashboard UI.
- `public/Sortable.min.js`: Local copy of SortableJS used for drag-and-drop.
- `data.json`: Persistent storage for links, categories, and settings.
- `Dockerfile` and `docker-compose.yml`: Container build and deployment config.
- `node_modules/`: Dependency tree generated by npm (do not edit by hand).

## Build, Test, and Development Commands
- `npm install`: Install dependencies.
- `node server.js`: Run the app locally on `http://localhost:3000`.
- `sudo docker compose up -d --build`: Build and run the containerized app (port 80).
No automated tests are currently configured.

## Coding Style & Naming Conventions
- Use 4-space indentation and semicolons to match existing JS style.
- Prefer clear, descriptive names (`openEditModal`, `syncLinks`, `status-dot`).
- Keep frontend logic in `public/index.html`; avoid introducing new build tooling.
- CSS uses variables for theme colors; add new colors to `:root`.

## Testing Guidelines
- There is no test framework or test suite in this repository.
- Manually verify:
  - Add/edit/delete links.
  - Drag-and-drop card and category reordering.
  - Status indicator updates.
  - Data persistence in `data.json`.

## Commit & Pull Request Guidelines
- Recent commit history uses short, imperative messages like `Add ...` or `Fix ...`.
- Keep commits focused and scoped to a single change set when possible.
- PRs should include:
  - A concise summary of changes.
  - Screenshots or short clips for UI changes.
  - Any manual test steps performed.

## Configuration & Data
- `data.json` is the single source of truth for saved links and settings.
- If you change the data shape, update both `server.js` and the frontend logic.
